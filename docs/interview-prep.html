30 秒电梯稿

ProfitOps AI 是一个跨境电商利润运营 Agent。它把“发现利润异常 → 归因 → 查运营规则 → 生成建议 → 人工审批 → 受控模拟执行”做成闭环。服务端用整数美分和确定性口径算利润与 8 项贡献桥，LLM 只做解释和工具选择，所有数字与证据由服务端校验；执行是幂等的模拟动作，全程可审计。默认离线可跑，真实模型可选。

2 分钟结构
  1. 问题广告、履约、退款、平台费吞掉利润；BI 只展示不闭环，通用聊天不可审计。
  2. 闭环分析图 → 审批暂停 → 执行图；持久化队列、租约、条件 UPDATE、唯一约束。
  3. 可信LLM 不碰钱；证据 ID 子集校验；RAG 可拒答；失败状态可见。
  4. 证据277 tests / 6 skipped；42 条 RAG 查询；22 + 12 次真实调用；边界是 demo auth、单 worker、模拟执行。

01

先做一个两分钟的自我介绍，重点讲这个项目。

高频开场叙事

考点 能否把业务问题、技术闭环、个人判断讲清楚；是不是一上来就堆技术栈。

参考答案 · 3 个追问
  • 30 秒定位：跨境电商利润运营 Agent，把“异常发现 → 归因 → 规则检索 → 建议 → 人工审批 → 模拟执行”做成闭环。
  • 三个技术支点：确定性账本（整数美分、8 项利润桥、证据 ID）；持久化工作流（LangGraph、数据库队列、租约 fencing、审批暂停）；受约束的 LLM/RAG（只解释和选工具，证据子集校验，可拒答）。
  • 结果：后端 277 passed / 6 skipped；前端 17 passed；RAG 42 条查询；Phase 2B 22 次 + native 12 次真实调用。
  • 边界：执行只做 simulation；认证是 demo 级；单 worker；6 篇合成 SOP。不要把作品集说成生产系统。

追问链

  1. 为什么先讲业务不讲技术？ 面试官要先知道价值，技术才有落点；技术栈可以后面按需展开。
  2. 一句话说清最有含金量的设计？ 钱由服务端算，LLM 只解释；审批暂停是持久化的业务状态，不是内存挂起。
  3. 只能保留一个模块，你保留什么？ 确定性利润 + 证据链，因为它是整个系统可信度的根。
雷区 背技术栈；把 demo 说成生产系统；只说“用了 LangGraph / RAG”而没有业务闭环。
02

为什么做这个项目？目标用户是谁？

高频动机产品

考点 动机是否真实、是否理解用户、能不能定义成功指标。

参考答案 · 3 个追问
  • 痛点：跨境卖家的利润被广告、履约、退款、平台费吃掉；BI 能看到结果但不下沉到动作；通用 chatbot 无法审计、不能审批。
  • 用户：运营负责人看异常和建议；分析师跑分析、查证据；approver 负责批准/拒绝和模拟执行。
  • 成功指标：分析完成率、建议采纳率、审批时长、fallback 率、no_answer 率、单次分析成本；不是 GMV。
  • 诚实边界：当前是作品集/演示系统，没有真实商家数据验证；下一步是找 1–2 个真实店铺做离线回放。

追问链

  1. 为什么不做预测或自动投放？ 先解决可信归因与审批闭环；自动投放风险更高，还需要真实外部系统。
  2. 怎么验证用户真的需要？ 访谈 + 合成数据可用性测试；目前没有生产数据，不能声称已验证 PMF。
  3. 商业化怎么做？ 订阅 + 按分析量；先证明能减少广告浪费或缩短审批周期。
雷区 说“为了学 LangGraph”；把个人项目包装成已有商业验证。
03

它和普通 LLM Demo、BI 报表有什么区别？

高频差异化系统设计

考点 是否理解系统边界与工程价值，而不是“接了个大模型”。

参考答案 · 3 个追问
  • BI：展示数字，不产生可审批动作，不校验 LLM。
  • 普通 LLM Demo：生成文本，数字可能错，失败不可见，不能暂停/恢复，不能防重复执行。
  • 本项目：服务端账本算钱；LLM 只解释/选工具；证据 ID 子集校验；LangGraph 持久化暂停；审批/执行条件 UPDATE + 唯一约束；模拟执行；评测。
  • 具体反例：模型把预算调整写成 30%，确定性 plan_action 给 15%，合并时以服务端计划为准；重复执行同一 key 返回原 execution，不会二次扣预算。

追问链

  1. 那 LLM 到底贡献了什么？ 归因叙述、根因假设、知识检索和建议文案；不贡献数字、权限和执行。
  2. 没有 LLM 能不能跑？ 能，deterministic_fallback 就是规则路径；LLM 是增强，不是单点。
  3. 这算 Agent 吗？ 有工具调用、状态、审批暂停和受控执行；但不是自主多 Agent，边界是刻意收窄的。
雷区 把“用了 LangGraph”当差异化；说不出一个 LLM 会犯、系统能拦住的错。

雷区 冒充手写；或者把责任全推给 AI，说“都是它写的，与我无关”。

05

为什么金额要用整数美分？

高频金额数据建模

考点 金额精度、边界条件、前后端一致性。

参考答案 · 3 个追问
  • 二进制浮点不能精确表示 0.1，聚合、退款、分摊会出现分差；金额统一存 BIGINT 美分，API 传整数，前端只在展示时除以 100。
  • 比率/利润率用 Decimal + ROUND_HALF_UP；分母为 0 返回 null，不返回 0。
  • 测试断言利润守恒和桥守恒；契约变更同步 backend/tests、frontend/src/types.ts、docs/CONTRACT.md。
  • 边界：单值远小于 JS 安全整数上限；多币种当前未实现。

追问链

  1. 分摊除不尽怎么办？ 明确舍入规则 + 最大余数法，测试总和守恒；当前没有复杂分摊。
  2. 多币种怎么加？ 存 currency + 最小单位 + 汇率快照；不同币种不能直接相加。
  3. 为什么不用 Decimal 存数据库？ 整数美分更简单、跨语言一致；Decimal 只用于比率计算。
雷区 “浮点只要格式化一下就行”；把“用 Decimal”说成所有金额都存 Decimal。
06

8 项利润桥怎么保证守恒？

高频利润口径可验证性

考点 利润口径、贡献方向、可验证性。

参考答案 · 3 个追问
  • net_sales = sales − discounts − refunds；net_profit = net_sales − cogs − ad_spend − fulfillment − platform_fees − other_costs。
  • 桥：sales 贡献 = current − previous；其余成本项贡献 = −(current − previous)；8 项之和必须等于净利润变化，bridge_verified 持久化。
  • 归因是会计贡献，不是因果证明；结论里明确写“不代表已证明业务因果”。
  • 测试覆盖正负贡献、零值、退款、缺数据；新增成本项要同步契约/模型/桥/类型/测试。

追问链

  1. 为什么成本项要取负？ 成本增加会减少利润，符号统一到“对利润的贡献”。
  2. 如果桥不守恒？ verify_evidence 抛 evidence_mismatch，不进入建议。
  3. 加一个新成本项要改哪些？ CONTRACT、models、metrics、schemas、types.ts、tests、docs；缺一个都可能漂移。
雷区 把贡献说成因果；只改前端不改契约；说不出符号规则。
07

退款为什么只冲收入，不重复扣采购成本？

中频业务口径退款

考点 业务口径与重复计算，能不能承认未实现的流程。

参考答案 · 3 个追问
  • 当前口径：refunds 已在 net_sales 中扣除；cogs 是已售商品成本，退款不自动回冲，否则同一笔成本扣两次。
  • 如果退货入库/可二次销售，需要单独的库存与成本恢复流程；当前没有实现，不能假装有。
  • 风险：退款跨期、部分退款、退款后广告费仍发生；当前按订单日期归期，跨期退款会在新周期体现。
  • 测试覆盖退款对 net_sales/net_profit 的影响和桥守恒。

追问链

  1. 部分退款怎么记？ 按退款金额冲收入；成本回冲需要退货状态，当前没有。
  2. 退款发生在下一周期？ 按业务日归期，会影响当期；需要跟财务口径确认。
  3. 广告费为什么不在订单里？ 广告是日级店铺/SKU 投放，来自 daily_operations，不是单笔订单。
雷区 说“退款把所有成本都退回来”；不区分会计口径和库存流程。
08

数据不完整为什么直接停止？缺失值当 0 不行吗？

高频数据质量产品决策

考点 数据质量意识，是否愿意为了可信度牺牲“看起来能跑”。

参考答案 · 3 个追问
  • 期望记录数 = 店铺 × SKU × 天数 × 2（当前 + 上一周期）；缺一条就标记 missing，incomplete 也算问题。
  • 缺失 ≠ 0：把没上报当成零会制造假异常/假建议；系统返回 insufficient_data（409），不生成可执行建议。
  • 前端展示缺失示例和 issues；用户补齐后重新分析。
  • 当前没有自动插值/补数；这是有意的边界，避免用假设污染利润。

追问链

  1. 迟到数据怎么办？ 重跑分析；生产要有数据水位/批次概念。
  2. 部分店铺缺失？ 当前整次分析失败；可按店铺隔离，但要先明确口径。
  3. 为什么不均值填补？ 经营数据缺失非随机，填补会伪造证据。
雷区 “先补 0 跑通再说”；把缺失当经营零值。
09

异常为什么定义为销售额上涨、净利润下降？零分母怎么处理？

中频指标定义边界

考点 指标定义、边界条件、null 的语义。

参考答案 · 3 个追问
  • anomaly = current.sales > previous.sales and current.net_profit < previous.net_profit；这是“增长不增利”的运营信号。
  • 销售额和利润都跌也算经营问题，但不是这个产品的触发条件；仍会展示报表，只是不自动建建议。
  • 变化率分母用 abs(previous)；previous=0 返回 null；margin 在 net_sales=0 时返回 null；前端显示“暂无数据”。
  • 不返回 0%，因为 0% 会掩盖“从无到有/从有到无”的无限变化。

追问链

  1. 为什么用 abs？ 负基数下保持变化方向语义一致。
  2. previous 为负怎么办？ 变化率仍可能失真，需要业务确认；当前返回数值但谨慎解读。
  3. 为什么不是利润下降就触发？ 增长不增利才是广告/履约效率问题的典型信号；避免所有波动都生成建议。
雷区 把 null 当 0；说“所有下降都是异常”。
10

时区、日期区间、数据量怎么处理？如果订单到千万级呢？

中频数据建模性能边界

考点 数据建模与性能边界，能不能承认当前没做过压测。

参考答案 · 3 个追问
  • 业务日统一 UTC；区间两端包含；分析最长 90 天；当前 + 上一周期等长。
  • 当前 fetch_metrics 按周期把 orders / daily_operations 读进内存聚合；60 天 seed 规模没问题，但千万订单需要下推 SQL 聚合、索引（tenant/store/date）、按日预聚合或分区。
  • 多店铺/SKU 通过 tenant_id + store_id 过滤；跨租户 404。
  • 时区转换应在入库前完成；当前没有多时区店铺。

追问链

  1. 索引怎么建？ (tenant_id, store_id, date) 覆盖查询；看执行计划。
  2. 预聚合表怎么保证一致？ 幂等重算 + 版本/水位；不能只增量。
  3. 90 天上限为什么？ 控制查询/内存/LLM 上下文；也是产品边界。
雷区 声称“支持千万级”但没有 benchmark；把 UTC 业务日和本地时区混着说。

11

为什么用 LangGraph？和普通函数、Celery、AutoGen 比呢？

高频技术选型Trade-off

考点 技术选型的 trade-off，而不是“框架流行”。

参考答案 · 3 个追问
  • 需要显式节点、条件边、持久化步骤状态、审批暂停/恢复、可视化轨迹；LangGraph 的 StateGraph 直接表达这些。
  • 普通函数：能跑，但暂停/恢复、步骤持久化、条件分支要自己写；Celery：任务编排强，但不表达业务状态机；AutoGen/CrewAI：多 Agent 自主协作，边界更难控，当前不需要。
  • 图：receive → metrics → profit → drivers → verify →（异常）retrieve → llm → verify_llm → recommendation → wait；执行是另一张图。
  • 代价：框架依赖、图版本管理、调试成本；所以关键校验仍在普通 Python 函数里，图只做编排。

追问链

  1. 为什么不用 Temporal？ 更重，当前单进程 demo 不需要；生产可评估。
  2. 图里怎么做条件边？ verify_evidence 后按 anomaly / insufficient_data 分支。
  3. 图代码升级，等待中的任务怎么办？ 当前没有图版本字段；生产要加版本/兼容。
雷区 “因为 LangGraph 火”；把框架当架构，讲不出业务状态。
12

wait_for_approval 是怎么暂停的？审批等三天，图还活着吗？

中频持久化状态机

考点 是否理解“业务暂停”与“内存挂起”的区别。

参考答案 · 3 个追问
  • 不是内存挂起；分析跑到 wait_for_approval 就把任务置为 waiting_approval，图的一次运行结束。
  • 审批 API 改 recommendation 状态；执行阶段用单独的 execution graph 从数据库加载，不重跑分析。
  • 进程重启/等三天都没关系；状态在 DB，不在 checkpoint 内存。
  • 审计记录每次状态变化；执行需要 approver + Idempotency-Key。

追问链

  1. 那 LangGraph 的 checkpoint 用了吗？ 没有把它当业务暂停；业务状态以 DB 为准。
  2. 审批后怎么恢复？ 执行图读 recommendation/analysis，条件 UPDATE approved → executing。
  3. 审批超时怎么办？ 当前没有过期；生产可加 TTL/提醒。
雷区 说“图一直挂在内存里等”；把框架 checkpoint 和业务状态混为一谈。
13

为什么自己写数据库任务队列？为什么不用 Celery/Redis？

高频队列一致性

考点 一致性、运维复杂度、故障模型。

参考答案 · 3 个追问
  • POST 只写 queued 行并返回；worker 用条件 UPDATE queued → running 抢占，写 worker_id/attempts/lease_until；心跳续租。
  • DB 是唯一事实源；不需要额外 Redis；任务状态、错误码、重试次数都能审计。
  • 适合单机/小规模；代价是轮询和 DB 压力。
  • 生产多副本可用 PostgreSQL SKIP LOCKED/行锁，或换成熟队列，但幂等/租约语义要保留。

追问链

  1. 条件 UPDATE 为什么原子？ 单条 SQL 的 WHERE 与 SET 在同一语句，rowcount=1 才算抢到。
  2. 心跳间隔/租约多长？ 租约要大于心跳间隔的几倍；当前实现有 heartbeat 续租。

压力题生产意识优先级

考点 生产意识、优先级，能不能明确说“现在不能上线”。

参考答案 · 3 个追问
  • 明确说：现在不能生产上线。缺生产身份（OIDC/SSO/MFA/密码重置）、分布式限流/指标、多副本 worker、密钥管理/备份/DR、真实数据导入与质量、LLM SLO/成本/降级、安全评审/压测/告警。
