# 开发方式与 AI 协作边界

本文件说明 ProfitOps AI 是怎么做出来的：哪些判断由本人负责，哪些代码由 AI 生成，以及外部如何核对。写它的目的不是免责，而是让这份代码的可信度可以被检验——包括检验“哪些不是他做的”。

## 1. 一句话结论

**本人是技术负责人，Claude Code 是执行编码的工程助手。**

规格、业务口径、契约、评测门禁、验收与合并决定由本人负责；具体实现（写代码、跑测试、补文档）由 Claude Code 在 `AGENTS.md` 的约束下完成。这个项目验证的不是“我能手敲两万行”，而是“我能把一个不可信的 LLM 组件做成可交付系统，并且让它的失败可见”。

## 2. 分工

| 环节 | 本人 | Claude Code |
|---|---|---|
| 业务问题定义（跨境卖家销售额涨、利润跌） | 提出、收敛 | 不参与 |
| 利润口径与公式（净销售额、净利润、8 项贡献桥、整数美分） | **定义并要求守恒** | 按定义实现 |
| API / 数据库 / 审批状态机契约（`docs/CONTRACT.md`） | **定义、审查变更** | 按契约实现 |
| 架构取舍（确定性计算与 LLM 分离、LangGraph 持久化暂停点） | **决策** | 提供方案与实现 |
| 评测设计（哪些必须门禁、什么算失败、负向对照） | **定义判定标准** | 搭建 runner 与样本 |
| 代码实现（后端 58 文件、前端 10 文件） | 审查关键路径 | **主要产出方** |
| 测试执行与验证记录（`docs/TEST_REPORT.md`） | 逐项核对结论 | 执行并记录 |
| 合并与发布决定 | **本人** | 不自动合并 |

## 3. 本人明确负责的判断（可在代码与文档中核对）

1. **利润绝不由模型计算。** 金额、环比、贡献桥、动作参数全部来自确定性代码；LLM 只输出解释与策略文案，且必须引用本次确定性证据的 `evidence_id`。这是整个项目的第一原则，不是实现细节。
2. **数据不足就不给建议。** 每日经营记录缺失或不完整时，Agent 停在 `insufficient_data`，宁可不出结论，也不让模型编一个。
3. **失败必须可见。** `llm_success` / `deterministic_fallback` / `llm_failed` / `not_requested` 四种状态在 API 与前端分开呈现；规则引擎的输出永远不伪装成 LLM 输出。
4. **RAG 可以拒答。** 低于阈值返回 `no_answer`，不拿低分片段凑答案；引用必须属于本次检索结果，未知 `chunk_id` 触发降级。
5. **审批是业务暂停点，不是内存等待。** 状态机与条件 UPDATE 保证并发下不会双重执行；执行幂等靠唯一约束而不是靠代码自觉。
6. **评测有硬门禁。** 门禁不通过时 CLI 退出码非 0；真实模型调用需要显式授权字符串与调用预算，不能顺手跑掉。
7. **不给结论加戏。** README 的“已知限制”逐条写明没做到什么（演示认证不是生产 IAM、样本小不能宣称准确率、mapping 不是语义模型）。

## 4. AI 完成的部分

后端业务代码、前端组件与样式、测试用例、迁移脚本、大部分技术文档初稿，由 Claude Code 生成后经本人核对与返工。自动化程度很高，因此**代码风格与文档密度的“过于整齐”是真实情况，不掩饰**。

## 5. 质量怎么控住

- `AGENTS.md` 是前置约束：禁止直接推 `master`、契约变更必须同步 `backend/tests` + `frontend/src/types.ts` + `docs/CONTRACT.md`、真实 LLM 不得进 CI、未实际执行的验证不得写成通过。
- 契约先行：先写 `docs/CONTRACT.md`（字段、金额单位、状态机、错误格式），再让实现对齐，最后测试反查。
- 三层验证：单元/集成测试（后端 272 项）→ HTTP 冒烟 → 真实浏览器 E2E（Playwright）。三层都跑过才算通过。
- 离线优先：评测默认用 `FakeToolProvider` 与录制回放，网络调用 0 次即可复现；真实调用单独授权、单独记录。
- 负向对照：评测不只有正例，还脚本化模型越权、参数非法、重复调用、未知引用，验证门禁真的会拦。

## 6. 外部如何核对

```bash
# 1. 代码规模与提交节奏
git log --oneline | wc -l          # 39 次提交，2026-10-30 → 11-03
git log --format="%ad %s" --date=short | head -40

# 2. 测试真的存在且能跑
python -m pytest backend/tests -q
npm --prefix frontend test -- --run
npm --prefix frontend run build

# 3. 评测真的离线可复现
.venv/Scripts/python.exe backend/evals/rag.py
.venv/Scripts/python.exe backend/evals/runner.py native

# 4. 约束真的写在仓库里
cat AGENTS.md
sed -n '1,60p' docs/CONTRACT.md
```

## 7. 边界之外（明确不主张）

- 不主张手写全部代码；不主张独立完成 1.9 万行 Python。
- 不主张生产可用：演示认证、进程内限流、单 worker、单机 Compose 都有明确记录的限制。
- 不主张评测结论等于准确率：合成案例上的门禁通过，只说明链路和门禁有效。
- 不主张 LLM 归因是因果证明：它是会计贡献项分解。
